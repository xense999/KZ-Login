## 產品目標（不因重寫而變）

1. 點 beanfun 帳號**頭像**（hover 浮出地球圖示，不另立按鈕）→ 開一個**帶著該帳號登入態**的內建瀏覽器視窗，預設開 `tw.beanfun.com`。
2. 有導覽列：上一頁／下一頁／重新整理／**可輸入的網址列**（只放行 http(s)，反 spoofing）。
3. 視窗可縮放、可記憶大小位置（實體像素、全帳號共用、螢幕拔掉時退回預設）。
4. 單一視窗組：他帳號的瀏覽器還開著 → 警告 toast、**絕不代關**（使用者兩次修訂的最終版）。
5. 網頁點出去的彈窗（金流常用）要能開、要保 `window.opener`、**且要帶登入態**。
6. 使用者 08-18 新增方向：彈窗／外開網址希望「像開分頁那樣」也有登入態——重寫時列入設計。
7. 預設尺寸 1230×720；外觀（邊框、圓角、配色）刻意未定案——**功能通了才回頭做外觀**。

## 第一版死因（2026-08-18 實測診斷，證據充分）

**Tauri 2 multi-webview（unstable，`Window::add_child`）的子 webview 在 Windows 上收不到鍵盤輸入。**

- 症狀：網址列（殼層）與 content 網頁**都**打不了字；使用者實機還會演變成整個 app 死當。
- 診斷過程（假 cookie 測試視窗＋Win32 探測自動化）：
  - 點任何一顆 webview 後，`GetGUIThreadInfo` 的 `hwndFocus` 停在頂層 `Tauri Window`（甚至變 NULL），從未進入 WebView2。
  - 從 Rust 呼叫 `Webview::set_focus()`（= `ICoreWebView2Controller::MoveFocus`）能把 Win32 焦點推進 `Chrome_WidgetWin_0`，**但鍵仍被 Chromium 丟棄**（autofocus 的輸入框收不到字）；殼層那顆打字瞬間焦點還會被彈回頂層。
  - 直接 `SetFocus` 到 `Chrome_RenderWidgetHostHWND`、補送 `WM_NCACTIVATE`/`WM_ACTIVATE` 都救不回——Chromium 視自己為「未啟用」而忽略鍵盤。
  - 對照組：同一個 app 的主視窗（單 webview、非 child）打字正常 ⇒ 問題出在 child 模式，不是我們的程式、不是 IME、不是 `transparent`（`transparent(false)` 已試、殼層透明與否無差）。
- 對應 wry 0.55.1 原始碼：單 webview 會在頂層掛 subclass（`WM_SETFOCUS`→`MoveFocus`），`is_child` 的容器（`WRY_WEBVIEW`）只有 `WM_SETFOCUS`→`SetFocus(child)`，而整條鏈上沒有任何機制把「activation」帶給 Chromium。
- 結論：**在上游修好之前，凡是「需要打字」的 UI 都不能放在 multi-webview 的子 webview 裡。**

## 連帶未結案（重寫時要重驗）

- **彈窗沒登入態**：第一版已做兩個修正（注入 cookie 加 6h 到期；注入不按網域過濾、jar 全注），但**從未在真帳號上驗證過**——當時使用者回報依舊，唯無法確認測的是不是修正後的 build。重寫時保留這兩個設計（理由見規範檔不變量），並用 `[browser] 準備注入 N 顆 cookie` 診斷行實測。
- **死當的確切機制**未坐實（英文 SendInput 下視窗不掛起）；懷疑是 IME 在焦點錯亂狀態下的後續，上游問題修掉後大概率一起消失。

## 使用者已拍板、重寫不得推翻的決策

- 入口＝頭像本身（hover 地球）；不另立按鈕。
- 跨帳號：警告、不代關。
- cookie 注入單向（app→webview）、登出不防呆（交給 ping_session）。
- 網址列是**安全需求**不是美化（content 無導覽限制＋帶登入 cookie＝spoofing 面）。
- 只在明確要求時 commit。

## 重寫路線候選（08-18 訪談用）

| 路線 | 樣子 | 代價 |
|------|------|------|
| A. 原生標題列 | 單 webview＋`decorations(true)` | **連導覽列（含網址列）都沒地方放**——單 webview 一載入外部網址我們的 UI 就不存在。網址列是安全需求，A 等於違規格，只能當臨時墊檔 |
| B. 雙視窗貼合 | 工具列＝自己的視窗（單 webview、打字天生正常）＋content＝另一個視窗（單 webview 載外部站），用 Windows owned window 綁在一起、移動/縮放連動 | 視窗連動要自己寫（Moved/Resized 同步）；「看起來像一體」的細節（拖動延遲、Alt-Tab、焦點切換）要打磨；**鍵盤是否全正常需先做丟棄式原型驗證** |
| C. 等/推上游 | 給 tauri/wry 報 issue（附本檔證據），修好後復活備份裡的原架構 | 時程不可控；可與 B 並行 |
