# 帳號瀏覽器登入態 — 診斷結論（2026-08-18）

> **2026-08-18 結案：使用者決定活動頁/SSO 登入這塊先不做。** 為此加的診斷碼與
> SSO 改動（warm_web_session、SameSite=None 注入、導航 log、cookie dump）已全數
> 移除，瀏覽器回到「能逛已登入官網、需 SSO 的頁面會要求登入」的乾淨狀態。
> 本檔保留為未來若重啟的脈絡。下方為當時的分析。

## 現象
- 網址列打 `tw.beanfun.com` → 有登入（cookie 帶到了）。
- 網頁點「遊戲啟動」→ 跳 `login.beanfun.com/Login/Index?pSKey=…` 的完整重新掃碼登入框。
- 活動頁 `maplestory-event.beanfun.com/Event/…` → 沒吃到登入（**與遊戲啟動同一根因**）。
- 剛重新掃 QR 登入後立刻測，仍跳 → 不是 session 過期。

## 統一根因
`tw.beanfun.com` 有登入＝它直接吃 `.beanfun.com` 的 `bfWebToken`（portal 自認 token）。
活動頁與遊戲啟動都要走 `login.beanfun.com` SSO 完整重授權——這層要 `login.beanfun.com` 域的登入 session，我們沒有。`.beanfun.com` 的 5 顆 token 活動頁讀得到（不是 cookie 沒帶到），是子系統拿 token 走 SSO 自動登入時卡在 login.beanfun.com。
凡走 SSO 重授權的頁面都失敗、凡直接吃 token 的都正常。

## 根因（已確定）
問題不在分頁、cookie 傳遞或 SameSite。是 **`login.beanfun.com`（SSO 登入服務）不接受我們 API 模擬 QR 登入留下的 session**。

我們的登入流程拿到的是 portal（tw.beanfun.com）的 `bfWebToken`：足以讓官網顯示已登入、取 OTP、啟動遊戲（走 GGM），但**從沒在 `login.beanfun.com` 建立可重用的 SSO 登入 session**。注入的 `GamaLoginSession` 對它無效。凡是網頁要求 SSO 重授權的動作（點遊戲啟動）都會被踢回登入頁。

## 已做且保留的改進（無害、對其他場景有益，但解不了本問題）
- `warm_web_session`：開窗前用 `auth.aspx?web_token` 升級 tw.beanfun.com portal 授權。
- 注入 secure cookie 設 `SameSite=None`：忠實度修正（reqwest jar 不存 SameSite，原本被注成 Lax，跨站導航會掉）。

## 讀 beanfun.rs 登入流程的發現（2026-08-18）
`finalize_qr` 最後一步：從 login.beanfun.com 拿「已登入證明」（SendLogin 的 hidden inputs）→ 立刻 POST 到 portal `return.aspx` 換 `bfWebToken`。login.beanfun.com 的登入在當下真的成立（jar 有 GamaLoginSession），但「交還授權給 portal」很可能消費掉它——SSO 常是一次性 login session。這解釋「剛登入完立刻測仍跳」：注入的 GamaLoginSession 是空殼，server 端已作廢。若屬實，「背景保存 login session」走不通。

## 待驗證的關鍵問題
瀏覽器裡跳出的就是真的 login.beanfun.com 登入頁——**當場掃碼登入一次後，活動頁/遊戲啟動能否正常用？**
- 能 → 方案＝需 SSO 的頁面在 webview 內當場掃碼（把章真的蓋進 webview），可再優化體驗。
- 不能 → 問題更深，需抓真實封包逆向。

## 方向選項
### A. 逆向 login.beanfun.com 的 SSO session 建立
抓官方瀏覽器登入 login.beanfun.com 的真實封包，找出它建立可重用 SSO session 的機制，在開瀏覽器時用 bfWebToken 重建。**大工程、不保證成功**（可能有加密/反爬）。

### B. 接受現況（重新界定瀏覽器用途）
內建瀏覽器用來逛**已登入的 tw.beanfun.com**（會員中心、儲值、活動公告）——這些現在就能用。「點遊戲啟動」在 app 本身已有原生功能（OTP／GGM 一鍵啟動），瀏覽器裡點它被要求重登，屬可接受。此路無需再投入。

### C. 折衷：瀏覽器內攔截「遊戲啟動」導向 app 原生流程
偵測到導向 login.beanfun.com 的 pSKey 授權時，不放行網頁，改觸發 app 既有的 GGM 啟動。（要確認遊戲啟動連結的可辨識特徵。）
